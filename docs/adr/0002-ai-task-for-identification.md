# Identification via HA AI Task, not direct provider calls

The identification step uses the core `ai_task` building block (`ai_task.generate_data`, shipped in HA 2025.8) instead of calling an LLM provider API directly from our integration. The user configures their AI provider (OpenAI, OpenRouter, Google, Ollama, ...) once in HA; AI Task gives us camera + local-file attachments and structured output for free, and we never handle credentials or provider-specific code. The trade-off: we depend on HA core >= 2025.8 and on its attachment-resolution behavior (note the 2026.5 camera HLS MIME regression, fixed in core PR #172682 — if identification ever fails with an unsupported MIME type, look there). Rejected alternatives: direct OpenAI-compatible API calls inside the integration (duplicated keys, provider lock-in, hand-rolled structured output) and the older `image_processing` domain (not LLM-based; face-recognition-oriented).

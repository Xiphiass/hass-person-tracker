# Tracker state lifetime: last-known-wins with TTL and authoritative demotion

Camera tracker state is last-known-wins: a Person stays at their last observed Location until either (a) no sighting for N minutes (TTL, default 30, configurable per person) or (b) the Person's optional authoritative tracker (e.g. their phone device_tracker) reports them away. Either way the state becomes "unknown" while last_location and last_seen attributes are retained, so staleness stays queryable. Rationale: a Person can be in camera blind spots for long stretches, so neither immediate expiry nor permanent last-known is right; the authoritative tracker catches the "they left the house" case that TTL alone handles too slowly. Rejected alternative: deriving this from HA's person entity - it cannot demote an individual tracker and would couple our behavior to the user's person configuration.

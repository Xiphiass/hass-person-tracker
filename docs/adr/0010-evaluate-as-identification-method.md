# Evaluate as an alternative identification method

HA 2026.11 added `ai_task.evaluate`: typed questions answered by the user's decision model with probabilities rather than free-form structured output. Identification can use it instead of `ai_task.generate_data` (ADR 0002), as a global setting that defaults to generate data and is only offered where HA has the action. Each Person gets one yes/no ("noul") question naming their reference photos and description, preceded by the re-check or move check framing where that applies; a detection run adds one question about anyone else in the frame. The answers are translated into the generate data response shape: a Person's probability becomes the hit's confidence, a Person below 0.2 is not reported (as generate data leaves out who it does not see, so an empty scene is not an uncertain sighting), and the "anyone else?" answer counts as one unknown person from 0.5. Everything after Identification (corroboration of ADR 0009, the minimum confidence, Unknown snapshots, re-checks and move checks) is shared by both methods. Rationale: a calibrated probability from a model built for decisions is a better confidence than one an LLM writes into JSON, and the user configures the decision model once in HA. Trade-offs: no bounding boxes, so last-seen thumbnails keep the full frame; one question per Person, so the decision model cannot itself rule out giving two Persons the same body (two hits on one person are possible where generate data says "at most one name each"); and the entity must support the evaluate feature, checked at setup and in the config flow. Rejected alternatives: one "choice" question over the Persons plus "no one"/"someone else" (cannot report several Persons in one frame); a "score" question for the number of unknown people (only "anyone or not" is needed to decide whether to keep the Snapshot); and replacing generate data outright (thumbnail crops, and providers without a decision model).

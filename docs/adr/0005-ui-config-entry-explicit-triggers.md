# Configuration is a UI config entry with an explicit camera-to-trigger map

All integration configuration lives in a single UI config entry, not YAML; entity pickers keep references valid as entities change. Settings shared by everyone - the camera->trigger map and the AI task entity used for identification - live in the entry itself and are edited through Reconfigure. Each Person is a config subentry (name, TTL, optional authoritative tracker) that can be added, edited, or removed on its own; the Person's tracker entity and device are keyed on the subentry ID, so renaming a Person keeps entity history. Rejected alternative: one entry per Person carrying its own camera map and AI task - the map is the same for every Person and would have to be repeated and kept in sync. The AI task entity is required and stored explicitly (the flow prefills HA's default AI task entity); there is no fallback to the HA default at runtime, so changing that default elsewhere in HA never silently switches the model identifying people. The camera->trigger map is explicit - each camera names its exact trigger binary sensor(s), with no same-device auto-detection default. Rejected alternative: auto-picking person/motion sensors from the camera's device - UniFi cameras expose several detection sensors (person, motion, sound) and the user must choose which one drives tracking; implicit selection would track on the wrong trigger. Reference images are the one thing outside the entry: files dropped into per-person config-dir folders (person_tracker/people/<person>/, looked up by the current name - after a rename the folder must be renamed too), picked up at setup and on reload.
